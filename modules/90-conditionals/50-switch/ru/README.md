
Многие языки в дополнение к условной конструкции _if_ включают в себя **switch**. Это специализированная версия _if_, созданная для некоторых особых ситуаций. Например, её имеет смысл использовать там, где есть цепочка _if else_ с проверками на равенство. Например:

<!-- check-csharp-blocks: skip — переменная status приходит извне примера -->
```cs
if (status == "processing")
{
    // Делаем раз
}
else if (status == "paid")
{
    // Делаем два
}
else if (status == "new")
{
    // Делаем три
}
else
{
    // Делаем четыре
}
```

Эта составная проверка обладает одной отличительной чертой: каждая ветка здесь — это проверка значения переменной `status`. Switch позволяет записать этот код короче и выразительнее:

<!-- check-csharp-blocks: skip — переменная status приходит извне примера -->
```cs
switch (status)
{
    case "processing":
        // Делаем раз
        break;
    case "paid":
        // Делаем два
        break;
    case "new":
        // Делаем три
        break;
    default: // else
        // Делаем четыре
        break;
}
```

Свитч — довольно сложная конструкция с точки зрения количества элементов, из которых она состоит:

- Внешнее описание, в которое входит ключевое слово `switch`. Переменная, по значениям которой _switch_ будет выбирать поведение. И фигурные скобки для вариантов выбора.
- Конструкции `case` и `default`, внутри которых описывается поведение для разных значений рассматриваемой переменной. Каждый `case` соответствует `if` в примере выше. `default` - это особая ситуация, соответствующая ветке `else` в условных конструкциях. Как и в случае с `else`, указывать `default` не обязательно.
- `break` завершает ветку и передаёт управление коду после _switch_. В C# выполнение не может «провалиться» из одного `case` в следующий, поэтому каждая ветка с кодом заканчивается `break`, `return` или другим оператором выхода. Без него программа не скомпилируется. Несколько меток `case` подряд без кода между ними допустимы, так одна ветка обрабатывает сразу несколько значений.

Если ветку с кодом оставить без `break`, компилятор остановится с ошибкой.

<!-- check-csharp-blocks: expect-error — ветка без break не компилируется -->
```cs
switch (answer)
{
    case 10:
    case 11:
        Console.WriteLine("Good!");
        break;
    case 12: // error CS0163: Control cannot fall through from one case label ('case 12:') to another
        Console.WriteLine("Better!");
    default:
        Console.WriteLine("Bad...");
        break;
}
```

Метки `case 10` и `case 11` идут подряд без кода между ними, поэтому обе ведут в одну ветку. Ветка `case 12` содержит код и не заканчивается `break`, и на ней сборка падает.

Фигурные скобки в _switch_ не определяют блок кода, как это было в других местах. Внутри допустим только тот синтаксис, который показан выше. То есть там можно использовать `case` или `default`. А вот внутри каждого `case` (и `default`) ситуация другая. Здесь можно выполнять любой произвольный код:

<!-- check-csharp-blocks: skip — переменная count приходит извне примера -->
```cs
switch (count)
{
    case 1:
        // Делаем что-то полезное
        break;
    case 2:
        // Делаем что-то полезное
        break;
    default:
        // Что-то делаем
        break;
}
```

Switch хоть и встречается в коде, но технически всегда можно обойтись без него. Ключевая польза при его использовании в том, что он лучше выражает намерение программиста, когда нужно проверять конкретные значения переменной. Хотя кода и стало физически чуть больше, читать его легче, в отличие от блоков _else if_.
